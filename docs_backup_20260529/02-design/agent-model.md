# Agent 人才库模式

**版本**: v2.0  
**日期**: 2026-05-15  
**状态**: 正式版  

---

## 1. 设计理念

传统的 Agent 系统通常采用「角色模板」模式——预定义好产品经理、架构师、开发等角色，然后从模板实例化。这种方式简单直接，但缺乏灵活性和个性化。

DevTeam-AI 采用「人才库」模式：

- **无预设角色**：Agent 不预设具体的职责和专业领域。每个 Agent 是具有独特个性的个体，在任务产生后才决定其具体职责和工作内容
- **任务驱动临时职责**：Agent 的职责是临时分配的，任务完成后回归原始状态。这模拟了真实团队中员工接受项目任务的工作模式
- **固定统筹**：设有一个固定的统筹 Agent，负责主导任务拆解、分配和进度管理，形成统一的团队协作风格

### 灰盒模型

任务调度整体是一个灰盒结构：

- 用户负责**发布任务和验收结果**
- 整体执行由**框架和 Agent 自行完成**
- 用户可以**随时查看内部执行细节**，但默认不需要关心

## 2. 个性定义

每个 Agent 通过 `soul.md` 文件定义其独特个性。核心维度为四个：

| 维度 | 可选值 | 说明 |
|------|--------|------|
| **性格类型** | 严谨型 / 创意型 / 务实型 / 协作型 | 决定 Agent 的思维方式和工作态度 |
| **沟通风格** | 简洁直接 / 详细解释 / 幽默风趣 | 决定 Agent 的表达方式 |
| **决策偏好** | 待定 | 决定 Agent 在不同场景下的决策倾向 |
| **风险倾向** | 待定 | 决定 Agent 面对不确定性的态度 |

### soul.md 示例

```markdown
# Agent Soul

## Core Principles
- 解决实际问题，而不是描述解决方案
- 保持简洁，除非用户需要深入讨论
- 知道就是知道，不知道就说不知道

## Execution Rules
- 单步任务立即执行，不要只是计划
- 多步任务先列出计划，等确认后再执行
- 写代码前先读代码，不假设文件存在
```

## 3. Agent 生命周期

### 状态流转

```
空闲 (idle) → 已分配 (assigned) → 执行中 (executing) → 已完成 (completed)
                                    ↓
                                 失败 (failed) → 回归空闲
```

### 状态说明

| 状态 | 说明 |
|------|------|
| `idle` | 空闲状态，等待统筹 Agent 分配任务 |
| `assigned` | 已接受任务，等待执行 |
| `executing` | 正在执行分配的任务 |
| `completed` | 任务完成，回归空闲状态 |
| `failed` | 任务执行失败，回归空闲状态 |

## 4. 独立上下文设计

每个 Agent 拥有完全独立的上下文空间：

| 属性 | 说明 |
|------|------|
| `conversation_history` | 独立的对话历史 |
| `memory_entries` | 三层记忆系统（L1/L2/L3） |
| `context_window` | 独立的上下文窗口 |
| `current_task` | 当前的临时职责 |
| `task_progress` | 任务进度追踪 |

---

## 5. 团队风格形成

固定的统筹 Agent 确保团队有统一的做事风格。团队整体的工作方式不靠预设，而是在**任务执行 → 复盘总结**的循环中逐渐形成。

---

## 6. 风险管理（待补充）

风险等级将通过**多维组合**评定，综合考虑：
- 操作类型（读数据 / 写代码 / 删文件 / 改系统配置）
- 影响范围（单文件 / 多模块 / 整个项目）
- 可逆性（git 可恢复 / 需手动恢复 / 不可逆）

由 Agent 根据标准评估，高风险操作需用户审批。
