# 分层记忆系统设计

**版本**: v3.0
**日期**: 2026-05-29
**状态**: 正式版  

---

## 1. 设计背景

Agent 在执行任务时需要依赖上下文信息，但 LLM 的上下文窗口有限，不可能将所有历史信息都加载进来。

分层记忆系统通过将信息按重要性和时效性分层，实现信息的高效存储和检索、上下文窗口的合理利用、以及长期知识的沉淀和复用。

本设计参考了 **CrewAI Cognitive Memory** 模型，将记忆视为主动认知过程，包含五个核心操作：**Encode（编码）→ Consolidate（合并）→ Recall（检索）→ Extract（提取）→ Forget（遗忘）**。

---

## 2. 架构总览

### 三层记忆 + 独立向量存储

```
┌─────────────────────────────────────────────────────────────┐
│ L1 工作记忆 (Working Memory) - Agent 私有                    │
│ • 当前会话的即时记忆                                          │
│ • 最近对话记录                                               │
│ • 任务中间结果                                               │
│ 生命周期：持久化到数据库，可跨会话保留                         │
├─────────────────────────────────────────────────────────────┤
│ L2 短期记忆 (Short-term Memory) - Agent 私有                 │
│ • 会话摘要                                                   │
│ • 重要决策记录                                               │
│ • 成功/失败经验                                              │
│ 生命周期：5-10 次会话                                         │
├─────────────────────────────────────────────────────────────┤
│ L3 长期记忆 (Long-term Memory) - Agent 私有                  │
│ • 核心技能                                                   │
│ • 领域知识                                                   │
│ • 成功案例                                                   │
│ 生命周期：永久                                               │
├─────────────────────────────────────────────────────────────┤
│ 向量存储 (Vector Store) - 团队共享                           │
│ • 任务总结                                                   │
│ • 可复用知识资产                                             │
│ • 复盘提取的抽象经验                                         │
│ 独立于记忆层级，所有 Agent 可检索                             │
└─────────────────────────────────────────────────────────────┘
```

### 关键边界

| 维度 | L1-L3 记忆 | 向量存储 |
|------|-----------|----------|
| 所有权 | Agent 私有 | 团队共享 |
| 访问方式 | Agent 自有 | 所有 Agent 可检索 |
| 写入方式 | 框架自动 | 需经讨论或统筹 Agent 决策 |
| 内容 | 个人经验积累 | 团队级别可复用知识资产 |

## 3. 记忆操作（CrewAI 五操作模型）

| 操作 | 说明 | 执行方式 |
|------|------|----------|
| **Encode** | 分析内容 → 分配分类、重要性评分 | 框架自动 |
| **Consolidate** | 检测与现有记忆的矛盾并合并 | 框架自动 |
| **Recall** | 语义检索 + 关键词检索 | 框架自动 |
| **Extract** | 从对话拆解为原子事实 | 框架自动 |
| **Forget** | 按质量/时间/容量策略遗忘 | 框架自动 + 复盘时手动触发 |

> **设计原则**：框架自动执行优先，不影响 Agent 功能。Agent 无感知记忆管理。

---

## 4. 记忆流转

### 晋升机制（L1 → L2 → L3）

记忆晋升由**双轨**驱动：

| 触发方式 | 说明 | 实现状态 |
|----------|------|---------|
| **日常自动规则** | 按访问频率、时间跨度、相关性评分自动晋升 | ✅ 已实现 |
| **复盘手动触发** | 大任务验收后，统筹 Agent 在复盘时手动晋升关键记忆 | ❌ 未实现 |

### 晋升规则

| 晋升路径 | 条件 |
|----------|------|
| L1 → L2 | 访问次数 ≥ 3，距今 ≥ 1 天，相关性 ≥ 0.3 |
| L2 → L3 | 访问次数 ≥ 10，距今 ≥ 30 天，相关性 ≥ 0.6 |

### 遗忘策略

- **质量遗忘**：综合质量分低于阈值自动清理
- **时间遗忘**：超过 365 天 + 90 天未访问自动清理
- **容量遗忘**：每层上限 100 条，总量上限 500 条
- **手动清理**：复盘时统筹 Agent 可手动标记清理

---

## 5. 记忆组织

记忆按**知识类型分类**，并**关联到具体任务**：

```
记忆条目
├── 分类：技术决策 / 问题解决 / 最佳实践 / 失败教训 / ...
├── 关联任务：任务ID
├── 标签：关键词列表
└── 内容：原子事实
```

---

## 6. 跨 Agent 知识共享

Agent 无法直接读取其他 Agent 的私有记忆。知识共享需通过以下途径：

1. **讨论过程**：Agent 在公共讨论中分享各自的知识
2. **统筹决策**：统筹 Agent 判断将知识写入共享向量库
3. **复盘沉淀**：大任务验收后，复盘产出写入共享向量库

## 7. 上下文压缩

当对话上下文超过 token 限制时，系统自动压缩以节省 token 使用。

### 压缩策略

| 策略 | 说明 |
|------|------|
| `AUTO` | 自动选择最佳策略 |
| `SUMMARY` | 使用 LLM 生成摘要 |
| `IMPORTANCE` | 基于重要性过滤，保留高价值消息 |
| `TOKEN_LIMIT` | 按 token 数量限制截断 |
| `MERGE_ADJACENT` | 合并相邻相似消息 |
| `TRUNCATE` | 简单截断旧消息 |

### 配置参数

- `max_tokens`: 最大 token 数（默认 4096）
- `importance_threshold`: 重要性阈值（默认 0.3）
- `preserve_system_prompt`: 保留系统提示（默认 true）
- `preserve_last_n_messages`: 保留最近 N 条消息（默认 3）

代码位置：`backend/app/services/memory/memory_compressor.py`

## 8. 记忆增强

记忆增强服务提供以下能力：

- **记忆衰减**：根据时间和访问频率降低记忆权重
- **记忆去重**：检测并合并重复记忆
- **隐私安全**：检测敏感信息并标记

代码位置：`backend/app/services/memory/memory_enhancement.py`

## 9. 与知识沉淀模块的关系

分层记忆系统负责**信息的存储和检索**。知识沉淀与自进化作为独立模块，负责：

- 从记忆中**提取可复用知识资产**
- 生成 **SKILL.md** 文件
- 发现模式并优化 Agent 行为准则

详见 [自我学习设计](./self-learning.md)。
