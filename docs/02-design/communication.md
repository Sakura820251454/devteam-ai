## 1. 通信模式

| 模式 | 说明 | 可见性 |
|------|------|--------|
| **公共讨论** | 所有 Agent 在公共频道中讨论，消息对全体可见 | 全员 |
| **阶段频道** | `stage:{project_id}:{stage_key}` 格式，按 Pipeline 阶段隔离 | 该阶段相关 Agent |
| **任务频道** | `task:{task_id}` 格式，特定任务的消息流 | 任务执行者 |
| **私聊** | 用户与单个 Agent 的私密对话 | 仅双方 |
| **主题订阅** | 按消息 metadata.topic 标签订阅，Agent 只收感兴趣的主题 | 订阅者 |
| **广播** | 系统向所有 Agent 发送通知 | 全员 |

## 2. 发布-订阅机制（v3.0 新增）

借鉴 MetaGPT 的共享消息机制，增强为多维度订阅：

- **按阶段订阅**：Agent 加入当前所在阶段的频道，只接收阶段相关消息
- **按主题订阅**：Agent 按话题类型（"架构设计"、"代码审查"、"测试"）订阅
- **前置阶段上下文**：`get_prerequisite_context()` 方法自动收集前置阶段消息
- Agent 不被无关消息淹没，讨论聚焦在当前任务阶段

## 3. 发言控制

### Token 预算管理

- 控制每次发言的最大 Token 数
- 跟踪会话级 Token 使用量
- 80% 使用率时触发警告

### 频率控制

- 限制 Agent 每分钟最大发言次数
- 可配置的最小发言间隔
- 防止 Agent 刷屏和资源浪费

### 辩论上限

- 同一议题设定辩论轮次上限
- 超上限自动上报用户裁决
- 平衡讨论充分性和 Token 成本

## 4. 消息类型

| 类型 | 说明 |
|------|------|
| `text` | Agent 文本消息 |
| `system` | 系统通知消息 |
| `action` | 操作消息（如任务状态变更） |
