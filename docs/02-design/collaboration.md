## 1. 协作模式

### 统筹 Agent 主导

设有一个固定的统筹 Agent，作为团队协作的中枢：

- **控场**：控制发言权，决定谁在什么时候发言
- **决策**：与用户共同做最终决策
- **协调**：管理任务拆解、分配和进度
- **复盘**：大任务验收后主导复盘总结

### Agent 举手机制

Agent 可以主动请求发言，由统筹 Agent 批准：

- Agent 判断话题与自身相关时，可向统筹 Agent 发出发言请求
- 统筹 Agent 根据当前讨论状态和请求优先级决定是否批准
- 所有 Agent 都能看到公共讨论内容，但不能发布与任务无关的消息

---

## 2. 讨论流程

```
统筹 Agent 提出议题
       ↓
相关 Agent 举手请求发言
       ↓
统筹 Agent 批准发言
       ↓
Agent 发表意见
       ↓
  ┌─ 达成共识 ──→ 记录决策，继续下一议题
  └─ 产生分歧 ──→ Agent 互相说服（有轮次上限）
                      ↓
                 达成共识 → 继续
                      ↓
                 超上限 → 上报用户裁决
```

### 分歧处理

当 Agent 意见不一致时：

1. **Agent 互相说服**：双方充分陈述理由，尝试达成共识
2. **轮次上限**：机制上设定辩论轮次上限，防止 Token 预算爆炸
3. **用户裁决**：超过上限仍未达成共识，上报用户做最终裁决

### 发言控制

- **不硬分模式**：不按阶段切换发言模式（顺序/轮询/优先级），灵活适应不同任务
- **频率限制**：防止 Agent 刷屏，限制每分钟最大发言次数
- **Token 预算**：控制每次发言的最大 Token 数，防止上下文窗口爆炸
- **全员可见**：公共讨论对所有 Agent 可见

---

## 3. 协作流程

```
用户发布任务
      ↓
统筹 Agent 主导需求分析
      ↓
Agent 民主讨论技术方案
      ↓
统筹 Agent 拆解任务 + 分配合 Agent
      ↓
Agent 并行执行子任务（DAG）
      ↓
执行 Agent 互相审核
      ↓
统筹 Agent 汇总结果
      ↓
用户验收
      ↓
复盘 → 沉淀知识
```

---

## 4. 用户介入

用户可随时在协作过程中介入：
- 聊天框输入自然语言指令
- 暂停 Agent 的错误行为
- 驳回不满意的结果要求重做
- 提出需求变更

详见 [干预系统](./intervention.md)。
