# 干预系统设计

**版本**: v2.0  
**日期**: 2026-05-15  
**状态**: 正式版  

---

## 1. 设计理念

干预系统是用户与 Agent 团队之间的控制通道。用户可以**随时主动介入**，不需要等待系统请求。

核心原则：

- **用户主导**：用户可在任何时候介入，不受系统状态限制
- **最小影响**：单 Agent 粒度的操作，不影响其他并行任务
- **简洁交互**：聊天框自然语言 + 一个停止按钮，不增加界面负担

---

## 2. 核心干预场景

仅支持三个核心场景，保持系统简洁：

### 2.1 纠错暂停

Agent 出现错误行为时，用户可立即暂停特定 Agent：

- 聊天框输入暂停指令（如"暂停小王，它写的代码有问题"）
- 仅暂停目标 Agent，不影响其他并行执行的分支
- 暂停原因会记录到该 Agent 的上下文中

### 2.2 结果驳回重做

执行结果不满足验收标准时，用户驳回并指派重做：

- 聊天框描述问题（如"这个 API 接口没做错误处理，重新写"）
- 系统将反馈注入 Agent 上下文
- Agent 基于反馈重新执行

### 2.3 需求变更

用户提出需求变更时，通知统筹 Agent 重新评估：

- 聊天框输入变更内容（如"现在需要支持多语言"）
- 变更消息发送给统筹 Agent
- 统筹 Agent 重新评估影响，调整任务计划

---

## 3. 干预方式

| 方式 | 说明 |
|------|------|
| **聊天框自然语言** | 用户直接输入干预指令，系统解析后执行 |
| **停止按钮** | UI 上唯一的干预按钮，一键停止所有 Agent |

不需要额外的操作按钮，保持界面干净。

---

## 4. 干预粒度

| 操作 | 粒度 | 影响范围 |
|------|------|----------|
| 暂停 Agent | 单个 Agent | 仅目标 Agent |
| 恢复 Agent | 单个 Agent | 仅目标 Agent |
| 替换 Agent | 单个任务 | 指定任务换人 |
| 修改任务 | 单个任务 | 调整任务参数 |
| 全局停止 | 全部 Agent | 整个流水线 |

---

## 5. 系统主动触发

除了用户主动介入，系统在以下情况也会请求用户介入：

| 触发条件 | 干预类型 |
|----------|----------|
| 高风险操作 | 请求审批 |
| 辩论超轮次上限 | 请求裁决 |
| Agent 错误率异常 | 通知用户 |
| 任务超时 | 自动暂停并通知 |

---

## 6. 断路器改造

原有的"错误率 > 30% 自动隔离 Agent"的断路器机制，改造为**恢复性修复**：

1. 检测到 Agent 状态异常
2. **清理当前上下文窗口**，移除可能已污染的信息
3. **从记忆系统重新加载**关键信息和任务上下文
4. 通知用户 Agent 已自动修复

**目的**：不是惩罚性地隔离 Agent，而是帮助 Agent 恢复正确状态。

---

## 7. 安全守卫

### 宪法原则（不可违背）

- 安全模块自身不可被修改
- 审计日志不可被删除或篡改
- Kill Switch 的优先级高于一切操作
- 人类审批链不可被自动化绕过

### Kill Switch

全局紧急停止，立即冻结所有 Agent 活动：

- 用户手动触发
- 断路器自动触发
- 严重违规自动触发
