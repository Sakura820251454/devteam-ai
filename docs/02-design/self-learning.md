## 1. 设计理念

知识沉淀与自进化是一个**独立模块**，与分层记忆系统协作但不耦合。

- **分层记忆系统**：负责信息的存储和检索
- **自我学习模块**：负责从记忆中提取可复用知识、生成技能、优化 Agent 行为

核心闭环：**执行 → 记录 → 复盘 → 提取 → 沉淀 → 复用**

---

## 2. 复盘机制

### 触发时机

**大任务验收后**触发复盘，而非每个子任务后。

例如：用户要求开发一个管理系统 → 系统开发完成 → 用户验收 → 触发复盘。

### 复盘过程

1. 统筹 Agent 汇总任务执行数据
2. LLM 分析执行轨迹、决策记录、产出结果
3. 提取经验教训和可复用知识
4. 按三条路径分别产出

> **⚠️ 实现状态**：当前复盘流程简化为直接由 pipeline 调用，未通过统筹 Agent 角色执行。LLM 轨迹分析未实现，只做简单日志提取。复盘在 pipeline 完成时触发（pipeline = 用户最初的需求，即"大任务"），子任务完成不触发。

---

## 3. 三条产出路径

复盘产出按性质分为三条路径：

```
复盘分析
   ├─ ① 流程最佳实践 → 生成 SKILL.md 文件 → 技能库
   ├─ ② 个体行为问题 → 生成 soul 优化建议 → 用户确认后更新
   └─ ③ 技术知识发现 → 存入共享向量库 → 等待检索
```

### 路径①：生成 SKILL.md

从多个相似成功案例中提炼标准化流程：

- 格式：标准 **SKILL.md** 文件，与 Agent 工具生态中的 Skill 格式完全一致
- 内容：流程步骤、检查清单、报告模板
- 使用方式：Agent 在后续任务中可直接加载使用

> **⚠️ 实现状态**：部分实现。当前生成的是数据库 Skill 对象（`skills` 表），非 SKILL.md 文件格式。

示例产出：

```markdown
# RESTful API 开发最佳实践

## 流程步骤
1. 分析数据模型 → 2. 定义路由 → 3. 实现 CRUD → 4. 添加错误处理 → 5. 编写测试

## 检查清单
- [ ] 所有端点有输入验证
- [ ] 错误响应格式统一
- [ ] 测试覆盖率 > 80%
```

### 路径②：优化 soul 行为规则

发现 Agent 反复犯同样错误时：

- 复盘生成**优化建议**（如"小王在写 API 时总是忘记加错误处理"）
- 建议提交给**用户确认**
- 用户确认后更新该 Agent 的 `soul.md` 文件
- **不允许自动修改 Agent 行为准则**，配置变更必须经用户确认

> **❌ 未实现**：soul 优化建议生成和确认流程未实现。当前只更新 growth.json，不修改 soul.md。

### 路径③：技术知识沉淀

发现可复用的技术知识时：

- 存入**共享向量库**
- 按知识类型分类，关联到具体任务
- 后续 Agent 可通过检索获取

> **❌ 未实现**：复盘产出到共享向量库的路径未实现。当前只生成 Skill 数据库对象。

## 4. 知识分类

### 显性知识

| 类型 | 说明 | 示例 |
|------|------|------|
| 技术文档 | 技术方案、架构文档 | 支付模块设计方案 |
| 最佳实践 | 经过验证的推荐做法 | 错误处理统一规范 |
| 代码片段 | 可复用的代码 | 通用分页查询实现 |
| API 规范 | 接口定义和约定 | RESTful 接口规范 |

### 隐性知识

| 类型 | 说明 | 示例 |
|------|------|------|
| 讨论共识 | 团队达成的决策 | 选择 PostgreSQL 作为主数据库 |
| 解决方案 | 问题解决的完整方案 | 高并发下缓存穿透的处理 |
| 成功案例 | 已验证的成功经验 | 订单系统重构项目复盘 |
| 失败教训 | 需要避免的错误 | 未加事务锁导致数据不一致 |
| 协作模式 | 高效的协作方式 | 前后端联调的最佳流程 |
| 用户介入准则 | **新增**：统计用户介入次数和原因，总结后作为执行准则 | 用户多次纠正 API 返回格式 → 形成格式校验规则 |

## 5. 知识应用

| 应用方式 | 说明 |
|----------|------|
| **自动匹配** | 执行任务时自动检索相关知识和技能 |
| **Agent 检索** | Agent 主动搜索知识库获取参考 |
| **技能加载** | 匹配到的 SKILL.md 自动注入 Agent 上下文 |

---

## 6. 模式发现

从多个任务执行数据中自动发现模式：

| 模式类型 | 说明 | 置信度要求 |
|----------|------|-----------|
| 成功特征 | 成功任务的共同因素 | 至少 3 个成功案例 |
| 陷阱模式 | 失败任务的共同原因 | 至少 2 个失败案例 |
| 协作模式 | 高效协作的共同特征 | 至少 5 个任务 |
| 技术栈模式 | 项目中频繁使用的技术 | 至少 3 个代码片段 |

> **❌ 未实现**：模式发现功能完全未实现。当前 `extractor.py` 只做简单关键词匹配分类，不涉及跨任务模式分析。
